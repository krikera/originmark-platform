# Support Resources for OriginMark

Welcome to the OriginMark community! We are committed to providing accessible and transparent support for developers, contributors, and users.

This document outlines the best ways to get help, ask questions, report bugs, or discuss feature ideas.

---

## 1. Getting Help & Asking Questions

### [GitHub Discussions](https://github.com/krikera/originmark-platform/discussions)
For general questions, implementation assistance, integration guidance, or architecture discussions, please use **GitHub Discussions**:
* **Q&A**: Ask how-to questions about using the FastAPI backend or Next.js dashboard.
* **Ideas**: Share proposals, use cases, or enhancement concepts before drafting a formal feature request.
* **General**: Connect with maintainers and other users working on digital provenance and cryptographic signing.

---

## 2. Reporting Issues & Proposing Features

### [GitHub Issues](https://github.com/krikera/originmark-platform/issues)
Before creating a new issue, please search existing issues to see if your topic has already been addressed.
* **Bug Reports**: If you encounter unexpected behavior or reproducible errors, please submit a report using our [Bug Report Form](https://github.com/krikera/originmark-platform/issues/new?template=bug_report.yml).
* **Feature Requests**: If you have a concrete feature suggestion, submit it via our [Feature Request Form](https://github.com/krikera/originmark-platform/issues/new?template=feature_request.yml).

---

## 3. Reporting Security Vulnerabilities

Please **do NOT** report security vulnerabilities via public GitHub issues.

* **GitHub Private Vulnerability Reporting**: Navigate to [Security Advisories](https://github.com/krikera/originmark-platform/security/advisories) and click **"Report a vulnerability"**.
* **Security Policy**: For detailed response SLAs and cryptographic disclosures, review our [Security Policy](SECURITY.md).

## 5. Support Expectations & Community Triage SLA

OriginMark is committed to responsive and transparent project maintenance. We observe the following triage and response Service Level Agreements (SLAs):

* **Bug Reports**: Maintainers review, verify, and acknowledge incoming bug reports within **3 to 5 business days**.
* **Feature Requests & Enhancements**: Proposals receive maintainer feedback and viability assessment within **7 business days**.
* **Security Vulnerabilities**: Initial acknowledgement within **48 hours** and a full remediation plan within **14 days**, as defined in our [Security Policy](SECURITY.md).
* **Weekly Triage Cadence**: Maintainers hold a regular weekly triage session to label, prioritize, and assign newly submitted community issues and pull requests.
* **Discussion Engagement**: [GitHub Discussions](https://github.com/krikera/originmark-platform/discussions) is monitored by maintainers and community ambassadors for general inquiries and technical architecture conversations.
